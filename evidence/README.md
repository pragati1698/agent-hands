These files were generated by the operator's local runs and supplied for review. Original event logs and failure-state snapshots are preserved byte-for-byte. No successful run was synthesized during review.

| `handoff-success/failure-state.json` | Sanitized structural state captured when intervention was requested; its filename does not mean the final run failed |

| `handoff-timeout/failure-state.json` | Latest intervention snapshot; snapshots overwrite within a reused evidence directory |

Handoff timing is calculated from control_transferred to resume_verified (49.26 seconds) or to the final paused result (120.16 seconds). The timeout reason is inferred from elapsed time and the operator's no-input test; the implementation does not emit a dedicated timeout event.

The operator's commands used discovery member 12345, replay member 67890 and unknown member 00000. Terminal output showed 9876.54 USD for successful replay. Member values and balances are not stored in event logs, so logs alone do not independently establish these input/output values.

## Review and limitations

The artifact was checked against the supplied Pydantic schema and the demo's action policy. Discovery checkpoint order agrees with the three artifact steps. All JSON/JSONL files parsed successfully. Reviewed files contained no detected API-key patterns or credential assignments; this is a bounded scan, not a universal privacy guarantee.

The client now requests strict structured output and retains safe validation diagnostics. Real successful discovery was performed after that correction. The earlier raw invalid model response was not saved.

No model calls occur in the replay engine. Provider responses and request IDs are not retained, so application logs are not independent API attestation. No per-run artifact hash or model snapshot was captured.
